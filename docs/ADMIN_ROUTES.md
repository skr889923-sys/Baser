# حذف المسارات من الإدارة

تتوفر **حذف المسار** في بطاقات الجوال وعمود الإجراءات على الحاسوب بصفحة `/routes`. يطلب الزر تأكيدًا يذكر اسم المسار وأثر العملية. الإلغاء لا يرسل طلبًا، وتبقى البيانات ظاهرة حتى تؤكد قاعدة البيانات حذف المسار نفسه.

يُحذف المسار وخطوات التوجيه وسجلات الرحلات المرتبطة به في معاملة قاعدة بيانات واحدة، حسب علاقات `ON DELETE CASCADE` الموجودة. تبقى نقاط التوجيه ورموز QR والمسارات الأخرى. إذا أردت إيقاف المسار مع الاحتفاظ بسجله، غيّر حالته إلى «مغلق» بدل حذفه.

بعد النجاح تُزال خطوات المسار من العرض، ويُختار مسار متبقٍ أو تُفرغ لوحة الخطوات عند حذف آخر مسار. تظهر رسالة عند رفض الصلاحيات أو تعذر تأكيد الحذف، ولا تعرض الواجهة نجاحًا لطلب لم يحذف صفًا. حدّث القائمة قبل إعادة المحاولة إذا تغيّرت البيانات أو انقطع رد الخادم.

تغيير الحالة والحذف متاحان لأدوار `super_admin` و`university_admin` و`building_manager`، مع بقاء التحقق من الصلاحيات في قاعدة البيانات. تحديث الحالة يغيّر رقم النسخة الزمني حتى لا يحذف طلب قديم مسارًا عُدّل لاحقًا.

لا يحتاج هذا الإصلاح إلى ترحيل SQL جديد على قاعدة طبّقت تحديثات صلاحيات الخرائط والسلامة التشغيلية السابقة. إذا كانت قاعدة مخصصة تمنع الحذف بسبب ارتباط آخر، تظهر رسالة بذلك؛ لا يحاول العميل حذف الخطوات منفصلة أو تجاوز القيود.

التحقق: `npm test` يشمل اختبار React فعليًا لحذف المسارات والإلغاء وفشل الصلاحيات والرد الفارغ وتكرار الضغط وتحديث التحديد. اختبار `supabase/tests/route_management.sql` يعمل عبر `scripts/test-map-permissions.py` مع `--safety-migration`، ويتحقق من الحذف المتسلسل والصلاحيات على الخطين القديم والجديد. ملف الاختبار محمي للتشغيل المحلي المؤقت فقط؛ لا يُنسخ إلى SQL Editor.
