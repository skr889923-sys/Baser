# شبكات الحرم في بصير

أضيف محرك شبكي مشترك في `packages/navigation`، وشاشة إدارة `/networks`، وشاشة جوال `/campus`. تبقى المسارات الداخلية القديمة في جداولها؛ الشبكات الخارجية تُحفظ كنسخ مستقلة، ولا تُحوّل نقاط الاختبار إلى جداول الإنتاج.

## ما تغير

- اختيار المسارات القديمة يستبعد المغلق والصيانة وغير المناسب قبل الترتيب. خيار «آمن ومهيأ» يشترط إتاحة الكرسي والتوجيه للمكفوفين معًا.
- شاشة التفاصيل لا تخترع نقطة بداية، ولا تحتفظ بنتيجة قديمة بعد تغيير التفضيل. يلزم QR صالح لتحديد البداية للمسارات الداخلية.
- محرك Dijkstra يختار مدخل المبنى المناسب، ويحترم الاتجاه الواحد والقياسات المجهولة وحالة الإغلاق. درجات السلم تتطلب العدد والارتفاع وحالة الدرابزين؛ الممر الخالي من الدرجات يتطلب قياس الميل. إتاحة `limited` لا تُقبل تلقائيًا للكراسي.
- حدود عرض 0.9 م وميل 8% هي قواعد مبدئية للتجربة من النموذج المرفق، وليست اعتمادًا هندسيًا أو معيارًا قانونيًا؛ يلزم أن يراجعها الفريق الميداني وفق المستخدمين والموقع.
- يستخدم الصوت تعليمات موثقة مستقلة لكل اتجاه. لا نعكس كلمات يمين/يسار آليًا، ولا نستنتج صعودًا من مقدار الميل المطلق. تعليمات المقطع يجب أن تتضمن تحذيراته وانعطافاته كاملة قبل النشر.

## تشغيل المعاينة

```sh
npm install
npm test
npm run dev:admin
```

افتح `/networks` واستورد `data/campus-fixture/network.json`. يمكن أيضًا تنزيله من زر «تنزيل نموذج الاختبار المصطنع». تظهر رحلة الكرسي من البوابة إلى الهندسة بطول 468 م للمدخل الجانبي، والأقصر بطول 365 م للمدخل الرئيسي ذي السلالم. زر النشر معطل لأن البيانات مصطنعة. الاستيراد والمعاينة محليان في المتصفح؛ التخزين يحتاج تسجيل دخول وجدول الشبكات.

## إعداد قاعدة البيانات

طبّق `supabase/migrations/20260906090000_campus_networks.sql` على مشروع Supabase المقصود بعد ترحيل المشروع الأساسي. التغيير ينشئ جدولًا جديدًا ولا يعيد تهيئة البيانات القديمة. لم تُطبَّق هذه الهجرة على Supabase المستضاف أثناء التنفيذ المحلي.

- الجمهور يرى فقط الصفوف المنشورة. المحررون: `super_admin` و`university_admin` و`building_manager` بحسب حساب المشروع.
- التخزين والنشر يستعملان رقم إصدار متزايد. محاولة حفظ نسخة قديمة تُرفض لتجنب طمس تعديل آخر.
- تمنع قاعدة البيانات نشر بيانات مصطنعة أو بلا دليل مسح ساري. التطبيق يكرر فحص البنية والهندسة والقياسات عند قراءة كل شبكة منشورة.
- حفظ شبكة منشورة كمسودة يسحبها من الإرشاد. زر نشر التحديث ينشر الإغلاق أو التعديل بعد اجتياز الفحص. الإغلاق ليس مؤقتًا بساعة تنتهي تلقائيًا؛ يلزم إعادة فتحه صراحة بعد المعاينة.
- مراجع الصور ومعرّف فريق المسح جزء من البيانات المنشورة. أدخل معرّف الفريق وصور المرفق؛ رفع الصور وإدارة تخزينها يتمان خارج هذه الشاشة، وهي تحفظ المراجع فقط.

لاختبار الهجرة والصلاحيات دون الاتصال بالإنتاج، مع توفر PostgreSQL محليًا:

```sh
python3 scripts/test-campus-database.py
```

الاختبار ينشئ خادمًا بملفات مؤقتة ومقبس محلي، وبيانات حسابات وهمية، ثم يوقفه ويحذف ملفاته. لا يستخدم إعدادات اتصال المشروع.

## تحضير بيانات QGIS

بعد تصدير `nodes.geojson` و`edges.geojson` و`buildings.geojson`:

```sh
node scripts/prepare-campus-import.cjs /path/to/export /tmp/campus-draft.json campus-pilot 'تجربة الحرم' 'Campus pilot'
```

الأداة لا تستبدل ملف خرج موجودًا. تضيف حقول الإصدار والأدلة الفارغة، وتحافظ على كون القياسات مجهولة، وتزيل ادعاء إتاحة الكرسي من العناصر غير المتحققة مع إظهار تنبيه. بيانات الإنتاج المستوردة تبدأ بإتاحة «لم يتم التحقق» ما لم تكن حالتها مسجلة صراحة. استورد الناتج وأكمل السجل في شاشة الإدارة.

حقول الإصدار الأول الإضافية لكل نقطة ومقطع:

| الحقل | المعنى |
|---|---|
| `survey_source` | رقم استمارة المسح أو مصدره القابل للمراجعة |
| `surveyed_by` | معرّف الفريق |
| `surveyed_at` | تاريخ المسح بصيغة ISO يتضمن المنطقة الزمنية |
| `valid_until` | موعد وجوب إعادة المراجعة، يحدده الفريق |
| `photo_refs` | مراجع الصور |
| `status` | `active` أو `closed` أو `maintenance` أو `unknown` |
| `closure_reason`, `closed_at` | سبب الإغلاق وتوقيته |
| `guidance_forward`, `guidance_reverse` | للمقاطع: كائن يحوي `instruction_ar` و`instruction_en` لكل اتجاه |

يلزم دليل ساري وقياسات كاملة وتعليمات للاتجاهات المسموحة لكل شبكة منشورة. إذا كان جزء من الموقع لم يُفحص، أبقه مسودة أو جهّز شبكة فرعية متصلة للممرات التي تحقق منها الفريق. لا تحوّل بيانات الاختبار إلى «حقيقية» بتغيير علامة `fixture`.

## استخدام الجوال وحدود التجربة

من الرئيسية اختر «التنقل بين مباني الحرم»، ثم الشبكة ونقطة الوقوف الفعلية والمبنى واحتياجات المسار. لا يُختار موقع البداية تلقائيًا من أول نقطة في القائمة. تُراجع الشبكة مجددًا قبل البدء وقبل الانتقال بين الخطوات؛ تغيير الإصدار أو انقطاع الاتصال أو انتهاء صلاحية الأدلة يوقف الإرشاد بدل الاستمرار ببيانات قديمة.

التقدم بين المقاطع يدوي بتأكيد المستخدم، كما في شاشة الملاحة الحالية. لم تُضف ملاحة GPS تلقائية مستمرة أو اتصالًا بلا إنترنت أو مراقبة فورية لحظة الإغلاق؛ التحقق يحدث عند البدء والانتقال بين الخطوات. في النسخة التجريبية يصاحب المستخدمَ فريقٌ ميداني.

الخطة والاستمارات العملية في `docs/pilot/FIELD_PILOT.md` و`docs/pilot/survey.csv` و`docs/pilot/walkthrough.csv`.
