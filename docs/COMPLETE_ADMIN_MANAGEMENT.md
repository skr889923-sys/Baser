# التعديل والحذف في أقسام الإدارة

طُبّق تحديث قاعدة البيانات على مشروع بصير `hpwcfgfebgvqkyerdzrh` في 2026-11-03 بعد موافقة المستخدم. أثبت الفحص المباشر للقراءة فقط وجود الوظائف الخمس وعمود ملاحظة الطوارئ، وإتاحة الاستدعاء للمصادقين مع منع دور `anon`. يبقى تحقق الأدوار داخل الوظائف نفسها كما اختُبر على المخططين محليًا. يمكن إعادة الفحص عبر [استعلام التحقق للقراءة فقط](../supabase/diagnostics/complete_admin_management_check.sql).

التحديث يكمّل إجراءات الإدارة العليا (`super_admin` و`university_admin`) في صفحات اللوحة، مع بقاء صلاحيات الموظفين المتخصصة السابقة. لا يكفي ظهور الزر لتجاوز الصلاحيات؛ وظائف قاعدة البيانات تتحقق من هوية المنفّذ ودوره والسجل المطلوب والحقول المسموحة والنسخة المعروضة.

| القسم | التعديل | الحذف |
| --- | --- | --- |
| المباني | النموذج الحالي للبيانات والموقع وحالة الظهور | المبنى وطوابقه بعد نقل نقاطه أو حذفها |
| نقاط التوجيه | البيانات والموقع والتوجيه الصوتي والطابق والحالات | النقاط غير المرتبطة بمسار أو QR |
| المسارات | الاسم والنوع والحالة والنهايتان والمدة وخصائص الوصول؛ إضافة الخطوات وتعديلها وترتيبها وإزالتها | المسار وخطواته وسجلات رحلاته بعد التأكيد |
| محرر الخريطة | روابط مباشرة لإدارة النقاط والمسارات | من صفحات الإدارة نفسها |
| شبكات الحرم | أسماء الشبكة وبيانات المسح والإغلاق والتعليمات؛ حفظ المسودة أو النشر بعد الفحص | كامل الشبكة المحددة مع التحذير من توقف إتاحتها للإرشاد |
| رموز QR | ربط النقطة والمحتوى والوصف بالعربية والإنجليزية | الرمز وسجل مسحه؛ تغيير المحتوى يستلزم طباعة ملصق جديد |
| البلاغات | العنوان والوصف والنوع والحالة وملاحظة الإدارة | حذف البلاغ نهائيًا، مع بيان توقف متابعة صاحبه |
| الطوارئ | ملاحظة الإدارة والحالة ضمن الانتقالات المسموحة | الطلبات المغلقة بعد المعالجة أو الإلغاء؛ لا تُحذف طلبات المساعدة المفتوحة |
| التعليق الصوتي | اسم الشخصية ونوعها؛ رابط التسجيل عبر HTTPS أو إعادة التسجيل الحالية | الشخصية وروابط تسجيلاتها أو ربط عبارة واحدة؛ الملفات الصوتية لا تُحذف لحماية المراجع المشتركة |
| المستخدمون | الاسم والهاتف واللغة والدور | حساب Auth وملفه؛ تمنع القيود حذف الحساب الحالي أو تعديل دوره |

مدير الجامعة لا يعدّل أو يحذف حسابات مديري النظام أو مديري الجامعة الآخرين، ولا يمنح هذين الدورين. مدير النظام يستطيع إدارة الحسابات الأخرى. تُسلسل عمليات الأدوار والحذف لتجنب حذف المديرين لبعضهم في اللحظة نفسها. إضافة صلاحية تستعمل حساب Auth موجودًا بالبريد نفسه؛ لم تعد تنشئ معرّفات عشوائية غير مرتبطة بحساب دخول.

## حفظ المسار وخطواته

يفتح نموذج التعديل أحدث مسار وخطواته من لقطة خادم واحدة. تُحفظ البيانات في معاملة واحدة: تُرفض النسخ القديمة، والخطوات غير المتصلة، والتعليمات الناقصة، والمسافات غير الموجبة، والمدة غير الصحيحة. تُحتفظ بمعرّفات الخطوات القائمة وبحقولها القديمة التي لم تُعدّل. فشل أي خطوة يتراجع عن تغيير المسار وجميع خطواته. تغيير نص توجيه مسجّل يلغي ارتباط تسجيله القديم حتى لا يُستخدم صوت يخالف التعليمات الجديدة.

## تحديث الخدمة

طبّق [تحديث الإدارة الشاملة](../supabase/migrations/20261103090000_complete_admin_management.sql) بحساب مالك قاعدة البيانات بعد تحديث صلاحيات الخرائط وخطوات المسار والسلامة التشغيلية. التحديث يضيف وظائف إدارية وعمود ملاحظة للطوارئ، ولا يحذف سجلات ولا يضيف بيانات اختبار. يتضمن أيضًا وظيفة حذف النقاط المحمي إذا لم يُطبّق تحديث أكتوبر الاختياري.

الوظائف الجديدة: `admin_manage_record` و`admin_attach_user_profile` و`get_route_for_edit` و`save_route_edit`. وظائف إدارة الحسابات تعمل بصلاحية مالك القاعدة، وتتيح التنفيذ للحسابات المصادقة مع رفض أي دور غير مصرح داخل الوظيفة. وظائف المسارات تبقي صلاحيات المستخدم وRLS قيد التنفيذ.

لا تُنسخ ملفات `supabase/tests/` إلى SQL Editor؛ هي اختبارات محلية محمية وتنتهي بالتراجع عن بياناتها وأدوارها. فحص المنطق والواجهة: `npm test`، وفحص البناء: `npm run build:admin`. اختبارات PostgreSQL تستخدم `scripts/test-map-permissions.py` مع خيارات الترحيلات السابقة و`--management-migration supabase/migrations/20261103090000_complete_admin_management.sql`، وتعمل على نسختي المخطط الأصلي والقديم.
